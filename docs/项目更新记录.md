## v1.8.4 — 2026-08-23

### 安全加固：GitHub 开源前专业代码审查修复

**后端（ApiServer.java / DatabaseHelper.java）**

- **密码哈希升级**: 无盐 SHA-256 → PBKDF2-HmacSHA256（120,000 迭代 + 16 字节随机盐，格式 `pbkdf2$iter$saltB64$hashB64`）；旧哈希在用户下次登录成功时自动透明升级；`DatabaseHelper.hashPassword/verifyPassword/needsRehash`
- **管理员权限校验**: `/api/admin/users*` 原先仅校验登录态，任意普通用户可增删改账号——现强制 `isAdmin()` 校验 admin 角色；删除接口保护 id=1 内置管理员
- **会话安全**: HashMap → ConcurrentHashMap（修线程安全）；新增 24 小时滑动过期（`sessionLastAccess`）；新增 `POST /api/auth/logout`；token 改为优先从 `Authorization: Bearer` 头读取（兼容旧 `?token=`）
- **路径穿越防护**: KB 导入仅允许配置的 KB 根目录内路径（拒绝 `?path=C:\Windows` 等任意目录）；附件删除限制在 `data/attachments` 内；静态文件服务改为规范化路径包含校验 + 禁止服务 `.bak/.log/.db/.md/.bat/.sh`
- **附件上传加固**: 文件名净化（剥离路径分量、长度≤150、字符白名单、扩展名黑名单 .exe/.bat/.js/.html/.svg 等）；base64 解码容错
- **KB 根目录可配置**: 移除硬编码个人云盘路径 → 环境变量 `KNOWLEDGE_KB_ROOT`（默认 `./KB`）；本地私有路径放 `config.local.bat`（已 gitignore），`start.bat` 自动加载
- **资源防护**: 每连接无限建线程 → 固定线程池（守护线程，acceptor 非守护维持 JVM 存活）；请求体上限 25MB（防 Content-Length OOM）；Content-Length 解析容错
- **并发正确性**: 路由分发整体 `synchronized(dbHelper)` 串行化（SQLite 单连接场景的正确性取舍）；SQLite 增加 `busy_timeout=5000`
- **其他**: 分享 token 从 16 hex 提升到完整 32 位 UUID hex；`jsonError` 完整 JSON 转义；错误响应不再回显内部异常信息；移除 `Access-Control-Allow-Origin: *`；注册/建号强制密码策略（≥8 位含字母数字）；角色字段白名单校验

**前端（web/）**

- `api.js`: token 改走 `Authorization: Bearer` 头，URL 不再携带 token（防日志/Referer 泄露）
- `index.html` / `share.html`: 新增 CSP（default-src 'self'，禁外链脚本与 iframe 嵌套）、nosniff、no-referrer
- `share.html`: `entry_type` 插入 class 前转义（XSS）
- `app.js`: 管理员编辑按钮 onclick 中 role 参数转义；版本号 v1.0.0 → v1.8.4

**仓库化准备**

- 新增 `.gitignore`（排除 data/数据库、build/、.gradle/、*.bak、冲突文件、config.local.*、opencode.md、jdk17/）

## v1.8.2 — 2026-08-20

### 新增功能：世界坐标护栏（布局边界）可视化

- **背景**: v1.8.1 修复后布局校验护栏为 ±10^6——数值上安全，但该范围即使缩放到最小档（20%）也远超视野，无法感知边界在哪
- **实现**（`web/js/app.js` `renderGraphCanvas`）: 护栏常量统一为 `WORLD_GUARD = 5000`，三处同源
  - **画布绘制**: `draw()` 在世界坐标层先绘制 ±5000 红色虚线框（`rgba(220,38,38,0.5)`，虚线段随缩放保持屏幕尺寸恒定），左上角标注「布局边界 ±5000」；随相机变换缩放/平移，缩小视图即可看到全貌；绘制在连线与节点之下不遮挡内容
  - **拖拽钳制**: 新增 `clampWorld()`，单节点拖拽与组拖拽的世界坐标均钳制于 [-5000, 5000]，节点到边界会被"挡住"（护栏语义）
  - **加载校验**: 布局恢复的合法性判断改用同一常量（替代 v1.8.1 的 10^6）
  - 图例提示区新增「红虚线框 = 布局边界」说明
- **设计要点**: 绘制/钳制/校验共用一个常量，保证不变式「框内位置必可保存、可保存位置必在框内」；现有数据最大坐标 1738，远在界内，零迁移
- **已验证**: `node --check` 通过；clampWorld 单测（6000→5000、-9999→-5000、1738/-80 原值保留）；刷新浏览器生效（纯前端改动）

## v1.8.1 — 2026-08-20

### Bug 修复：图谱节点拖到负坐标区域后重进页面位置错乱

- **现象**: 知识图谱页面把节点（尤其向上/向左）拖动后切换页面，重新进入图谱时该节点位置"乱放"，回落到环形布局上的某个点；再次拖拽其它节点保存后，错误位置被固化
- **根因**（`web/js/app.js` `renderGraphCanvas` 布局恢复校验）: 恢复保存位置时的合法性判断为 `saved.x >= 0 && saved.y >= 0`，把**负世界坐标判为非法**。而 mousemove 绑定在 `window` 上、节点可拖出画布边界（往上越过顶边 y<0），或平移视图后向左上拖拽，都会产生合法的负坐标。这些节点每次加载都被丢弃位置 → 回落环形自动布局 → 表现为"位置保存乱了"
  - 后端 `graph_layouts` 表与 GET/POST 接口本身对负号无任何限制，数据一直存对了，是前端加载环节丢弃的
- **修复**: 校验改为「数值有限且绝对值 ≤ 10^6」——接受任意负坐标，仅拦截非数值/异常超大值（护栏保留）
- **验证**:
  - 新旧判定逻辑对比单测：负坐标 old=ring-fallback / new=restore；超大值与非数值两者均拒绝
  - API 全链路：POST 含负坐标布局 → GET 完整返回 `-150/-80` 等，往返无损
  - 测试期间曾用仅含 2 个节点的布局覆盖全表，已按事先留存的完整快照原样恢复（78 节点）
- **文档同步（维护）**
  - `docs\功能设计文档.md`: 3.7 布局保存说明更新（负坐标合法，仅非数值/超 10^6 回落）
  - `docs\数据库字典.md`: graph_layouts 保存策略说明同步更新

## v1.8.0 — 2026-08-20

### 新增功能

- **KB 目录导入变更同步**: 个人知识库 KB 源文件修改时间（mtime）变化时，重新导入自动覆盖更新对应条目/记录，实现"KB 改动 → 平台同步"
  - 平台记录每个 KB 条目的源文件相对路径 `kb_source` 与最后修改时间 `kb_mtime`
  - 导入判定：源文件 mtime **晚于**平台记录值 → 覆盖更新内容与摘要，并重新解析双链；内容无变化则跳过
  - 首次升级运行导入时（历史条目 `kb_mtime` 为空）自动建立同步基线（覆盖一次并记录时间戳），之后仅同步真正变更的文件
  - 乱码自愈（含 `\uFFFD` 的旧内容强制修复）逻辑保留并合入同步判定
  - 导入结果新增统计：`entries_updated`（条目同步更新数）/ `records_updated`（记录同步更新数）
  - 前端数据管理页导入结果展示同步更新数量

### 技术变更

- `server/src/main/java/com/knowledge/DatabaseHelper.java`: `knowledge_entries` / `work_records` 各新增 `kb_source TEXT DEFAULT ''`、`kb_mtime TEXT DEFAULT ''` 列（CREATE TABLE 内 + 历史库 `ALTER TABLE ADD COLUMN` try/catch 迁移）
- `server/src/main/java/com/knowledge/ApiServer.java`:
  - `/api/import/kb` 计数器扩展为 `long[8]`（新增 `entries_updated`/`records_updated`），返回 JSON 新增两字段
  - 新增 `kbSourceOf()`（相对 KB 根路径，`/` 分隔）与 `mtimeOf()`（毫秒时间戳）辅助方法
  - `importKbEntry`/`importKbRecord` 重写已存在分支：原 `fixCorruptedEntry`/`fixCorruptedRecord` 废弃，合入新的 `syncEntryIfChanged`/`syncRecordIfChanged`（mtime 变化/首次同步/乱码 → UPDATE 覆盖，并重新解析双链）
- `web/js/app.js`: `importKb()` 结果展示追加「条目同步更新 / 记录同步更新」两行

### Bug 修复

- `syncRecordIfChanged` 跳过时双重计数导致 `records_skip` 翻倍（131 计为 262），改为由同步函数内部统一计数后修复

- **修复**（`server/src/main/java/com/knowledge/ApiServer.java`，KB 导入段）:
  ```
  String kbRoot = query.getOrDefault("path", "");
  if (kbRoot.isEmpty()) kbRoot = DEFAULT_KB_ROOT;   // 空串也回退默认路径
  ```
  即：无论缺键还是空串，统一回退 `DEFAULT_KB_ROOT`（迁移后默认路径本身有效，KB 根目录在云盘未被移动）

### 运维修复：compile.bat 找不到 Java 编译器

- **现象**: 迁移至云盘目录后 `compile.bat` 报 `[ERROR] Java compiler not found. Set JAVA_HOME or install JDK 11+.`
- **根因**: 机器级环境变量 `JAVA_HOME` 仍指向已不存在的旧升级包 JDK 路径（`D:\Projects\OpenCodeProject\jdk17\jdk-17.0.2`），`if exist "%JAVA_HOME%\bin\javac.exe"` 不成立、PATH 中 javac 也缺失
- **修复**:
  1. `compile.bat`: 探测顺序调整为 **相对 JDK → 系统 JAVA_HOME → PATH**，优先使用 `%BASE%..\jdk17\jdk-17.0.2`（与 `start.bat` 相对定位一致，随目录搬迁自动生效）
  2. 用户级/机器级 `JAVA_HOME` 同步更新为新 JDK 路径（`服务器正在运行中的新路径`；新开终端生效）
